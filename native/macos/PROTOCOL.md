# lmr-capture-helper protocol

Authoritative reference, generated by reading `native/macos/Sources/main.swift` directly
(previously referenced from `CLAUDE.md`/`ARCHITECTURE.md` but missing; the sketch that used
to live inline in `ARCHITECTURE.md` had drifted from the real implementation — see
"Corrections" below). The Python side implements this in
`src/local_meeting_recorder/capture/protocols.py` and
`src/local_meeting_recorder/capture/macos/helper_client.py`.

## Transport

JSON lines on stdin (commands) / stdout (events); diagnostics on stderr. One JSON object
per line, no embedded newlines. The helper exits when stdin reaches EOF, so a crashed
parent can never leave a recording running.

Two ways to run it:
- **Command loop** (no arguments): reads commands from stdin until EOF, as below.
- **One-shot**: `lmr-capture-helper probe|list-displays|request-permissions|--version|--help`
  prints one JSON line (or help text) and exits immediately — no stdin loop.

## Commands (Python → helper)

| Command | Fields | Notes |
|---|---|---|
| `{"cmd": "ping"}` | | replies `pong` |
| `{"cmd": "probe"}` | | permissions snapshot without prompting |
| `{"cmd": "request-permissions"}` | | triggers the TCC prompts if not yet determined |
| `{"cmd": "list-displays"}` | | |
| `{"cmd": "start", ...}` | see below | fails with `already_recording` if one is active |
| `{"cmd": "stop"}` | | fails with `not_recording` if none is active |

`start` fields (defaults shown; all but `output_path` optional):

| Field | Default | |
|---|---|---|
| `output_path` | *required* | must not already exist; parent dirs are created |
| `display_id` | main display | |
| `capture_microphone` | `true` | **not** `capture_mic` |
| `microphone_device_id` | none | |
| `fps` | `30` | clamped 1–60 |
| `video_bitrate_kbps` | `6000` | min 500 |
| `audio_bitrate_kbps` | `128` | clamped 32–320 |
| `max_dimension` | `1920` | longest side; min 320 |
| `shows_cursor` | `true` | |
| `stats_interval_s` | `5.0` | min 0.5 |
| `min_free_mb` | `512.0` | below this, a `warning` is emitted on every stats tick |

## Events (helper → Python)

| Event | When | Key fields |
|---|---|---|
| `ready` | once, at process start | `version`, `protocol`, `pid`, `macos` |
| `pong` | reply to `ping` | |
| `probe` | reply to `probe` | `version`, `protocol`, `macos`, `permissions: {screen, screen_preflight, microphone}` |
| `permissions` | reply to `request-permissions` | flat: `screen`, `screen_preflight`, `microphone`, `screen_request_result`, `microphone_request_result` |
| `displays` | reply to `list-displays` | `displays: [{id, name, width, height, pixel_width, pixel_height, is_main}]` |
| `started` | recording began | `output_path`, `display_id`, `width`, `height`, `fps`, `capture_microphone`, `tracks: [{index, kind, role?, codec}]` — **no `session_id`** |
| `stats` | every `stats_interval_s` while recording | `elapsed_s`, `bytes`, `free_mb`, plus per-source counters: `video_frames`, `system_audio_buffers`, `mic_audio_buffers`, drop/skip counters, and (once the writer session has started) `first_video_offset_s`, `first_system_audio_offset_s`, `first_mic_audio_offset_s`, `media_duration_s` |
| `warning` | async, e.g. low disk | `code`, `message`, `free_mb?` |
| `error` | any command/runtime failure | `code`, `message`, `fatal`, plus `permission` for `permission_denied` |
| `stopping` | always precedes `stopped` | `reason` |
| `stopped` | recording finalized (or failed to) | same counters as `stats`, plus `reason`, `finalized`, `output_path`, `bytes`, `duration_s`, `error` (set only when `finalized` is false) |

Permission values: `granted` \| `denied` \| `restricted` \| `not_determined`.

Error codes: `bad_command`, `unknown_command`, `permission_denied`, `display_not_found`,
`output_exists`, `writer_setup_failed`, `capture_failed`, `stream_stopped`, `write_failed`,
`disk_full`, `stop_timeout`, `already_recording`, `not_recording`.

## Lifecycle

- One helper process is good for **one recording**. After a clean `stop`, the process exits
  on its own (exit code reflects success/failure) — Python must spawn a fresh helper for the
  next recording. A helper used only for `probe`/`list-displays`/`request-permissions` stays
  alive until its stdin is closed.
- On stdin EOF with an active recording, the helper stops and finalizes exactly as if `stop`
  had been sent, then exits. On SIGINT/SIGTERM/SIGHUP, same behavior.
- A hung `stopCapture`/`finishWriting` is bounded by a 25 s internal watchdog
  (`stop_timeout` error, then exit).

## Corrections versus the original ARCHITECTURE.md sketch

The design sketch written before the helper existed got several things wrong once the real
implementation (950 lines of `main.swift`) was written against it. Fixed here, in
`capture/protocols.py`, and in `ARCHITECTURE.md`:

1. The microphone field is `capture_microphone`, not `capture_mic`.
2. Nothing in the protocol carries a `session_id` — ever. The helper only ever knows an
   output path; session identity is entirely a Python-side concept.
3. `stats` is a rich multi-field counter payload, not `{elapsed_s, frames, audio_bytes}`.
4. `permissions` is not emitted unsolicited; it is nested under `probe`'s response for a
   passive check, or returned flat as the response to `request-permissions` (which the
   sketch did not mention at all, along with `ping`).
5. `displays` entries carry `pixel_width`/`pixel_height`/`is_main`, not just `width`/`height`.
6. Every `error` carries a `fatal` boolean; the sketch's example omitted it.
7. A `stopping` event always precedes `stopped`; the sketch did not mention it.
